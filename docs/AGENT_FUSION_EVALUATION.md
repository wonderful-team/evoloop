# 缺失功能与 Agent 融合评估

## 评估维度

| 维度 | 说明 |
|------|------|
| **Agent 需求度** | Agent 是否需要此功能才能更好工作 |
| **实现复杂度** | 开发成本 |
| **用户价值** | 对非 Agent 用户的价值 |
| **建议优先级** | 综合建议 |

## 2. 子任务（parent_id）

### 功能描述
支持任务层级结构

### Agent 融合评估

```
场景分析：
┌─────────────────────────────────────────────────────────────┐
│ 场景 1：任务拆解（Agent 核心能力）                            │
├─────────────────────────────────────────────────────────────┤
│ 用户: "实现用户登录功能"                                      │
│                                                             │
│ 当前 Agent 做法：                                             │
│ 1. 创建一个任务："实现用户登录功能"                            │
│ 2. 在 Plan 中创建步骤：                                       │
│    - Step1: 设计数据库表                                      │
│    - Step2: 实现 API 接口                                     │
│    - Step3: 前端页面                                          │
│                                                             │
│ 问题：任务和计划步骤割裂，无法关联                              │
├─────────────────────────────────────────────────────────────┤
│ 有子任务后：                                                  │
│ 1. 创建父任务："实现用户登录功能"                              │
│ 2. 创建子任务：                                               │
│    - SubTask1: 设计数据库表 (parent=父任务ID)                  │
│    - SubTask2: 实现 API 接口                                  │
│    - SubTask3: 前端页面                                       │
│ 3. Agent 可以追踪整个任务树进度                                │
└─────────────────────────────────────────────────────────────┘
```

```
场景分析：
┌─────────────────────────────────────────────────────────────┐
│ 场景 2：复杂任务执行                                          │
├─────────────────────────────────────────────────────────────┤
│ 当前 Agent 面对复杂任务：                                       │
│ - 无法表达"完成 3/5 个子任务"                                  │
│ - 只能扁平化创建多个独立任务                                    │
│ - 难以表达任务间依赖和顺序                                      │
│                                                             │
│ 有子任务后：                                                  │
│ - Agent 可以分阶段执行：                                        │
│   "完成用户模块（父任务）的第一阶段：数据库设计（子任务1）"        │
│ - 可以追踪整体进度百分比                                        │
│ - 支持分阶段交付和验收                                          │
└─────────────────────────────────────────────────────────────┘
```

| 评估项 | 评分 | 说明 |
|--------|------|------|
| Agent 需求度 | ⭐⭐⭐⭐⭐ 极高 | 任务拆解是 Agent 核心能力，需要层级表达 |
| 实现复杂度 | ⭐⭐⭐ 中 | 需要改表结构 + 树形查询 |
| 用户价值 | ⭐⭐⭐ 中 | 普通用户也需要子任务 |

## 3. 看板视图

### 功能描述
按状态分组的任务可视化

### Agent 融合评估

```
场景分析：
┌─────────────────────────────────────────────────────────────┐
│ 用户: "展示看板"                                              │
├─────────────────────────────────────────────────────────────┤
│ Agent 能做什么：                                              │
│ - 调用 API 获取任务列表                                        │
│ - 按 status 分组统计                                           │
│ - 返回："待处理 5 个，进行中 3 个，已完成 10 个"                │
│                                                             │
│ Agent 不能做什么：                                            │
│ - 渲染 GUI 看板界面                                            │
│ - 拖拽操作                                                     │
└─────────────────────────────────────────────────────────────┘
```

| 评估项 | 评分 | 说明 |
|--------|------|------|
| Agent 需求度 | ⭐ 低 | Agent 不需要 GUI，只需要数据 |
| 实现复杂度 | ⭐⭐ 低-中 | 前端工作为主 |
| 用户价值 | ⭐⭐⭐⭐ 高 | 用户需要可视化 |
| **建议优先级** | **P2** | 前端优化，Agent 不依赖 |

### Agent 融合建议
```python
@tool
def get_kanban_summary(project_id: int) -> str:
    """
    获取看板摘要（供 Agent 汇报用）
    返回文本形式的看板状态
    """
    tasks = get_unified_tasks(project_id)
    
    # 按状态分组统计
    by_status = group_by(tasks, 'status')
    
    return f"""
    📋 项目看板摘要
    ━━━━━━━━━━━━━━━━━━━━━━━━
    🆕 待处理: {len(by_status['pending'])} 个
    🔄 进行中: {len(by_status['in_progress'])} 个
    ✅ 已完成: {len(by_status['completed'])} 个
    ━━━━━━━━━━━━━━━━━━━━━━━━
    总计: {len(tasks)} 个任务
    
    高优先级待处理:
    {list_high_priority(by_status['pending'])}
    """

# Agent 使用示例
# > "项目进度怎么样？"
# Agent: get_kanboard_summary(project_id=1)
```

### 结论
**⏸️ 延后实现** - 纯 UI 功能，Agent 可以通过文本统计实现类似效果

## 4. 离线缓存

### 功能描述
本地缓存 EvoCloud 项目数据，支持离线查看

### Agent 融合评估

```
场景分析：
┌─────────────────────────────────────────────────────────────┐
│ 场景 1：无网络环境                                            │
├─────────────────────────────────────────────────────────────┤
│ 用户: "查看我的项目"                                          │
│ Agent: "当前无网络，但我可以展示缓存的项目列表"                 │
│                                                             │
│ 但问题是：                                                    │
│ - Agent 依赖 LLM，LLM 需要网络                                │
│ - 没有 LLM，Agent 无法理解和响应                              │
│ - 即使缓存了项目数据，Agent 也无法工作                          │
├─────────────────────────────────────────────────────────────┤
│ 场景 2：弱网环境                                              │
├─────────────────────────────────────────────────────────────┤
│ 用户: "创建任务：修复bug"                                      │
│ Agent: 理解意图 → 准备创建 → 网络失败 → 提示稍后重试            │
│                                                             │
│ 离线缓存的价值：                                              │
│ - 可以查看项目信息（只读）                                     │
│ - 可以创建本地待办（稍后再同步）                                │
│ - 但不能让 Agent 做复杂工作                                     │
└─────────────────────────────────────────────────────────────┘
```

| 评估项 | 评分 | 说明 |
|--------|------|------|
| Agent 需求度 | ⭐⭐ 低-中 | Agent 主要依赖 LLM，LLM 需要网络 |
| 实现复杂度 | ⭐⭐ 中 | 需要缓存策略、同步冲突处理 |
| 用户价值 | ⭐⭐⭐ 中 | 用户可查看，但 Agent 受限 |
| **建议优先级** | **P2** | 锦上添花，非必需 |

### Agent 融合建议
```python
# Agent 不需要专门的离线工具
# 但需要知道当前网络状态

@tool
def check_connectivity() -> str:
    """
    检查 EvoCloud 连接状态
    Agent 根据状态调整行为
    """
    if is_offline():
        return "当前离线，我只能访问本地缓存数据，无法创建云端任务"
    return "在线状态良好"

# 离线时 Agent 的行为调整
# - 只读操作：正常（使用缓存）
# - 写操作：提示用户稍后重试，或创建本地 Todo
```

### 结论
**⏸️ 低优先级** - Agent 依赖 LLM，LLM 需要网络，离线价值有限

## 结论与建议

### 对 Agent 最重要的功能

1. **子任务 (P0)**
   - Agent 的任务拆解和执行规划需要层级结构
   - 没有子任务，复杂任务只能扁平化处理
   - **必须实现**

2. **统一视图 (P1)**
   - 降低 Agent 查询复杂度
   - 避免遗漏任务来源
   - **推荐实现**

### 对 Agent 价值有限的功能

3. **看板 (P2)**
   - Agent 处理数据，不处理可视化
   - 纯前端工作
   - **延后**

4. **离线缓存 (P2)**
   - Agent 依赖 LLM，LLM 需要网络
   - 离线时 Agent 能力大打折扣
   - **延后**

### 最终建议

**先做子任务**，这是 Agent 能力的基础设施。

**后做统一视图**，优化 Agent 的查询体验。

**看板和离线缓存**可以按需实现，与 Agent 融合关系不大。
