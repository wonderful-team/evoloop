# EvoLoop 项目管理系统分析

## 一、当前架构概览

```
┌─────────────────────────────────────────────────────────────┐
│                    项目管理层 (Project Domain)                  │
├─────────────────────────────────────────────────────────────┤
│  API Routes (projects.py, tasks.py, todos.py, etc.)         │
├─────────────────────────────────────────────────────────────┤
│  Domain Services                                            │
│  - service.py (ProjectContextManager)                       │
│  - sync_service.py (project_sync_service)                   │
│  - discovery_manager.py                                     │
│  - requirements/service.py                                  │
├─────────────────────────────────────────────────────────────┤
│  Models                                                     │
│  - Repository (本地代码库)                                   │
│  - TodoItem (本地待办)                                      │
│  - ProjectRequirementDocument/Analysis/Task (需求管理)       │
│  - Plan/PlanStep (执行计划)                                  │
│  - AutonomousTask (自主任务)                                │
├─────────────────────────────────────────────────────────────┤
│  External Integration                                       │
│  - EvoCloud API (远程项目管理)                               │
│  - Project Discovery Watcher (本地项目发现)                   │
└─────────────────────────────────────────────────────────────┘
```

## 二、功能清单

### 2.1 已实现功能

| 模块 | 功能 | 存储位置 | 备注 |
|------|------|---------|------|
| **项目基础** | 项目CRUD | EvoCloud | 远程管理 |
| | 项目发现 | Local SQLite | 自动扫描 WORKSPACE_ROOT |
| | 项目结构缓存 | Memory | AnnotatedTreeGenerator |
| **任务管理** | 项目任务CRUD | EvoCloud | 与远程同步 |
| | 本地Todo | SQLite | 独立表，不与远程同步 |
| **需求管理** | 需求文档上传 | Local SQLite | docx/pdf/xlsx/md/txt |
| | AI需求分析 | Local SQLite | Agent分析 + 人工确认 |
| | 任务拆解 | EvoCloud | 分析结果同步到远程任务 |
| **计划管理** | 执行计划 | SQLite | Plan/PlanStep 本地存储 |
| **工时管理** | Timesheet | EvoCloud | 依赖会员权限 |
| | Budget | EvoCloud | 预算管理 |
| **代码库** | Repository索引 | SQLite | SourceFile/CodeEntity/CodeChunk |
| **自主任务** | AutonomousTask | SQLite | 定时/周期任务 |

### 2.2 模型关系

```
Project (EvoCloud)
    ├── Tasks (EvoCloud)
    ├── Requirements (Local SQLite)
    │       ├── ProjectRequirementDocument
    │       ├── ProjectRequirementAnalysis
    │       └── ProjectRequirementTask (同步到EvoCloud)
    ├── Repositories (Local SQLite)
    │       └── SourceFile → CodeEntity/CodeChunk
    ├── Todos (Local SQLite) - 独立
    └── Conversations (Local SQLite)
            ├── Plan → PlanStep
            └── Messages
```

### 3.2 🟡 架构问题

#### 数据分散问题
```
┌──────────────┐    ┌──────────────┐    ┌──────────────┐
│   EvoCloud   │    │  Local SQLite │    │   Memory     │
├──────────────┤    ├──────────────┤    ├──────────────┤
│ • Projects   │◄──►│ • Repos      │    │ • TreeCache  │
│ • Tasks      │    │ • Todos      │    │ • Context    │
│ • Budget     │    │ • Plans      │    └──────────────┘
│ • Timesheet  │    │ • Conv       │
└──────────────┘    │ • AutoTasks  │
                    │ • Requirements│
                    └──────────────┘
                          │
                    ┌─────┴──────┐
                    ▼            ▼
              ┌─────────┐  ┌─────────┐
              │  Wiki   │  │ Memory  │
              │ Module  │  │ Module  │
              └─────────┘  └─────────┘
```

**问题：**
- 项目数据分散在 3+ 个存储中
- 事务一致性难以保证
- 离线模式与在线模式切换复杂
- 备份/恢复困难

#### 概念混淆

| 概念 | 问题 |
|------|------|
| **Task** | 项目任务(EvoCloud) vs 计划步骤(PlanStep) vs 自主任务(AutonomousTask) vs TodoItem |
| **Project** | EvoCloud项目ID vs 本地Repository关联 |
| **需求** | 需求文档 → 分析 → 任务拆解流程过长，无快速任务创建 |

### 3.3 🟢 冗余/过度设计

#### A. 功能冗余
| 功能 | 说明 | 建议 |
|------|------|------|
| **AutonomousTask** | 与 EvoCloud Tasks 重叠 | 合并或明确分工 |
| **TodoItem** | 与 EvoCloud Tasks 重叠 | 考虑合并 |
| **Plan/PlanStep** | 与项目任务无关联 | 整合到任务系统 |
| **需求管理流程** | 文档→分析→确认→拆解→同步 | 过于复杂，支持快速创建 |

#### B. 过度抽象的队列系统
```
当前: Factory → Celery/Huey/Local
问题: 
- 简单项目管理系统需要 3 种队列后端？
- Huey (SQLite) 已满足嵌入式需求
- Celery 仅用于服务器模式

建议: 
- 嵌入式模式：Huey (已实现✅)
- 服务器模式：可考虑简化为 Huey + Redis
```

#### C. 同步机制复杂
```
当前: 本地项目 ←→ EvoCloud 双向同步
     + Repository 状态管理
     + 需求任务同步
     + 工时同步

问题:
- 同步逻辑散落在多处
- 冲突处理机制不明确
- 离线编辑后同步困难

建议:
- 明确主从关系（本地为主或云端为主）
- 统一同步层
```

## 四、改进建议

### 4.1 短期（1-2周）

1. **统一任务视图**
   - 将 TodoItem、PlanStep、AutonomousTask 统一展示
   - 添加 `source` 字段区分来源

2. **简化需求流程**
   - 支持快速创建任务（跳过文档→分析→拆解流程）
   - 保留完整流程作为高级选项

3. **项目上下文增强**
   - 统一项目上下文获取方式
   - 缓存优化减少重复扫描

### 4.2 中期（1-2月）

1. **本地项目管理系统**
   - 不依赖 EvoCloud 的完整项目管理
   - 可选同步到云端
   - 支持导入/导出

2. **任务关联增强**
   - 任务 ↔ 代码提交关联
   - 任务 ↔ 会话关联
   - 任务 ↔ Wiki 关联

3. **看板视图**
   - 状态驱动的看板
   - 拖拽操作

### 4.3 长期（3-6月）

1. **项目模板系统**
   - 敏捷模板
   - 瀑布模板
   - 自定义模板

2. **里程碑与甘特图**
   - 可视化时间线
   - 依赖关系图

3. **协作功能**
   - 分享项目（只读/编辑）
   - 评论系统

## 六、决策建议

### 选项 1: 保持现状（推荐短期）
- 继续依赖 EvoCloud 进行项目管理
- 专注于 AI 辅助开发的核心价值
- 本地只保留开发相关数据（代码索引、对话、计划）

### 选项 2: 增强本地项目管理（推荐中期）
- 建立完整的本地项目模型
- 可选同步到 EvoCloud
- 支持离线工作

### 选项 3: 与专业工具集成
- 提供 Jira/Linear/Notion 集成
- 作为 AI 辅助层
- 不重复造轮子
